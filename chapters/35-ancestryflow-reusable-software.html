35  AncestryFlow: building reusable bioinformatics software

This case study grows as its implementation is verified. The current checkpoint covers an installable Python package and 37 tests covering sample-ID validation, text-file input, exact sample selection, VCF-header reading, the VCF-aware command-line interface and sample extraction. At checkpoint 18, GitHub Actions verified the then-current 31 tests and the installed sample-validation command on Python 3.11, 3.12, 3.13 and 3.14. The package below does not estimate ancestry yet.

35.1 Why a biologist should care

An analysis script often works only with its author’s paths and sample names. A reusable tool needs explicit inputs, clear errors and tests that another researcher can run. Here we build toward reference-based ancestry estimation, beginning with one small component: sample-ID validation.

All examples use invented donor names. No controlled-access genotypes or donor-level results are included.

35.2 Engineering objective

Create an installable Python package whose validation function can be imported by another program. This section covers completed checkpoints 1–22: repository setup, an isolated environment, package configuration, validation, tests, development dependencies, the first Git commit, text-file input, a command-line interface, CLI integration tests, a feature commit, exact sample selection, VCF-header reading, CLI integration, a documented feature commit, public GitHub publication, an MIT license, automated tests on GitHub a sample-extraction function, its CLI command compressed VCF output and a runnable synthetic example.

35.5.4 4. Implement sample-ID validation

Create src/ancestryflow/samples.py:

"""Validation utilities for sample identifiers."""

from collections.abc import Iterable


def validate_sample_ids(sample_ids: Iterable[str]) -> list[str]:
    """Return sample IDs in their original order after validation.

    Raises:
        TypeError: If the input is a single string or contains nonstrings.
        ValueError: If IDs are empty, contain whitespace, repeat, or are absent.
    """
    if isinstance(sample_ids, (str, bytes)):
        raise TypeError("Provide a collection of sample IDs, not a single string.")

    validated: list[str] = []
    seen: set[str] = set()

    for position, sample_id in enumerate(sample_ids, start=1):
        if not isinstance(sample_id, str):
            raise TypeError(f"Sample ID at position {position} must be a string.")

        if not sample_id:
            raise ValueError(f"Sample ID at position {position} is empty.")

        if any(character.isspace() for character in sample_id):
            raise ValueError(f"Sample ID contains whitespace: {sample_id!r}")

        if sample_id in seen:
            raise ValueError(f"Duplicate sample ID: {sample_id!r}")

        seen.add(sample_id)
        validated.append(sample_id)

    if not validated:
        raise ValueError("At least one sample ID is required.")

    return validated

The function preserves exact names and order. It rejects whitespace instead of silently changing an identifier that must later match a VCF header. Exceptions let the caller choose how to report errors. At this stage it validates names only; it does not check whether those names exist in a VCF.

"""Tests for sample identifier validation."""

import pytest

from ancestryflow.samples import validate_sample_ids


def test_preserves_sample_order():
    samples = ["donor_02", "donor_01"]
    assert validate_sample_ids(samples) == samples


def test_accepts_a_generator():
    samples = (f"donor_{i}" for i in range(3))
    assert validate_sample_ids(samples) == ["donor_0", "donor_1", "donor_2"]


@pytest.mark.parametrize(
    "samples, message",
    [
        ([], "At least one sample ID"),
        ([""], "is empty"),
        ([" donor_01"], "contains whitespace"),
        (["donor 01"], "contains whitespace"),
        (["donor_01\n"], "contains whitespace"),
        (["donor_01", "donor_01"], "Duplicate sample ID"),
    ],
)
def test_rejects_invalid_ids(samples, message):
    with pytest.raises(ValueError, match=message):
        validate_sample_ids(samples)


@pytest.mark.parametrize(
    "samples",
    ["donor_01", b"donor_01", [123], ["donor_01", None]],

The parameterized tests exercise several inputs independently. A generator is accepted; a single string is rejected because treating it as an iterable would otherwise process individual characters as sample names.

35.5.7 8. Read sample IDs from a text file

The next verified component accepts a filename, reads one exact sample ID per line and reuses the validator. The file has no header. Blank lines and whitespace within an ID are rejected; a normal final newline is accepted.

In src/ancestryflow/samples.py, add from pathlib import Path with the imports and add this function:

def read_sample_ids(path: str | Path) -> list[str]:
    """Read and validate a file containing one sample ID per line.

    Blank lines, duplicate IDs and whitespace within IDs are rejected.
    File access errors propagate to the caller.
    """
    text = Path(path).read_text(encoding="utf-8-sig")
    return validate_sample_ids(text.splitlines())

Path(path) accepts a filename string or a Path object. read_text() reads the file; utf-8-sig also handles a UTF-8 byte-order mark that some editors add. splitlines() removes line endings without silently stripping spaces from IDs. Missing-file and access errors propagate to the caller.

In tests/test_samples.py, replace the existing function import with:

from ancestryflow.samples import read_sample_ids, validate_sample_ids

Append these tests:

def test_reads_sample_file(tmp_path):

def test_rejects_blank_line_in_sample_file(tmp_path):

35.5.8 9. Expose the library as a terminal command

Create src/ancestryflow/cli.py:

"""Command-line interface for AncestryFlow."""

import argparse
from pathlib import Path

from ancestryflow.samples import read_sample_ids


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(
        prog="ancestryflow",
        description="Tools for reference-based genetic ancestry analysis.",
    )

    commands = parser.add_subparsers(dest="command", required=True)

    validate = commands.add_parser(
        "validate-samples",
        help="Check a file containing one sample ID per line.",
    )
    validate.add_argument(
        "--samples",
        type=Path,
        required=True,
        help="Sample-list file without a header.",
    )

    args = parser.parse_args(argv)

    try:
        sample_ids = read_sample_ids(args.samples)
    except (OSError, ValueError) as error:
        parser.error(str(error))

    print(f"Validated {len(sample_ids)} sample IDs.")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

argparse reads command-line arguments and generates help text. The validate-samples subcommand provides room for future analysis commands. --samples is required and converted to a Path. The CLI reuses read_sample_ids() instead of copying validation rules.

parser.error() prints a useful message to standard error and exits with status 2. Successful validation returns 0. These statuses let scripts and workflow engines detect success or failure. The optional argv argument also lets tests supply arguments directly without changing the process’s global arguments.

Append this separate table to pyproject.toml:

[project.scripts]
ancestryflow = "ancestryflow.cli:main"

It registers a terminal command named ancestryflow that calls main() in the package’s cli module. Reinstall from the project root to register it in the active environment:

    assert result.returncode == 0
    assert result.stdout.strip() == "Validated 2 sample IDs."
    assert result.stderr == ""

    sample_file = tmp_path / "samples.txt"
    sample_file.write_text("donor_01\ndonor_01\n", encoding="utf-8")

    result = run_cli("validate-samples", "--samples", str(sample_file))

    assert result.returncode == 2
    assert "Duplicate sample ID" in result.stderr
    assert result.stdout == ""


def test_cli_missing_file(tmp_path):
    missing_file = tmp_path / "missing.txt"

    result = run_cli("validate-samples", "--samples", str(missing_file))

    assert result.returncode == 2
    assert "missing.txt" in result.stderr

These five integration tests launch a separate Python process. They verify help, valid input, duplicate IDs, a missing file and a missing required argument. A successful exit has status 0; the argparse-based CLI reports these input errors with status 2.

Code Purpose
subprocess.run() Runs the command in a separate process
sys.executable Uses the Python interpreter running pytest
-m ancestryflow.cli Executes the CLI module
capture_output=True Captures normal output (stdout) and error output (stderr) for assertions
text=True Returns captured output as strings
timeout=10 Fails the test if the command takes more than ten seconds
returncode Reports the process’s exit status

The helper deliberately does not use check=True: error exits are expected in the negative tests, so the assertions inspect their status and messages directly. tmp_path isolates test inputs from real sample files. No additional dependencies are required.

35.5.11 12. Match requested sample IDs exactly

Before extracting genotypes, compare the requested names with the names available in the VCF. This checkpoint implements the comparison independently of file parsing, so it can be tested without genotype data.

Append this function to src/ancestryflow/samples.py:

def validate_sample_selection(
    requested_ids: Iterable[str],
    available_ids: Iterable[str],
) -> list[str]:
    """Validate exact sample matches and preserve the requested order.

    Raises:
        TypeError: If either collection contains invalid types.
        ValueError: If IDs are invalid or requested samples are absent.
    """
    requested = validate_sample_ids(requested_ids)
    available = set(validate_sample_ids(available_ids))

    missing = [
        sample_id
        for sample_id in requested
        if sample_id not in available
    ]

    if missing:
        raise ValueError(
            "Requested samples not found: " + ", ".join(missing)
        )

    return requested

Both collections pass through the existing validator. A set makes membership checks efficient; the returned list preserves the requested order. All absent names are reported together. Matching is exact and case-sensitive: a prefix such as donor_01 must not silently select donor_01-extra.

In tests/test_samples.py, include validate_sample_selection in the import from ancestryflow.samples, then append:

def test_selection_preserves_requested_order():
    requested = ["donor_02", "donor_01"]
    available = ["donor_01", "donor_02", "donor_03"]

    assert validate_sample_selection(requested, available) == requested


def test_selection_reports_all_missing_samples():
    requested = ["donor_01", "missing_01", "missing_02"]
    available = ["donor_01"]

    with pytest.raises(ValueError, match="missing_01, missing_02"):
        validate_sample_selection(requested, available)


def test_selection_rejects_prefix_matches():
    with pytest.raises(ValueError, match="Requested samples not found"):
        validate_sample_selection(["donor_01"], ["donor_01-extra"])


def test_selection_is_case_sensitive():
    with pytest.raises(ValueError, match="Requested samples not found"):
        validate_sample_selection(["donor_01"], ["DONOR_01"])

35.5.12 13. Read sample names from a VCF header

Use pysam’s VariantFile reader to access header sample names without scanning variant records.

Inside the existing [project] table in pyproject.toml, immediately below requires-python, add:

    "pysam==0.24.1",

This is a runtime dependency: users need it to read variant files. The exact version is selected by ==. Installing a direct dependency at a fixed version is useful, but does not lock the entire environment. From the project root with the environment active, install the updated configuration:

python -m pip install -e ".[dev]"

Create src/ancestryflow/vcf.py:

"""Utilities for reading variant-file metadata."""

from pathlib import Path

import pysam

from ancestryflow.samples import validate_sample_ids


def read_vcf_samples(path: str | Path) -> list[str]:
    """Read and validate sample IDs in VCF header order.

    This checks sample identifiers, not variant records or genotype quality.
    File-opening and parsing errors propagate to the caller.
    """
    with pysam.VariantFile(str(path)) as variant_file:
        return validate_sample_ids(variant_file.header.samples)

The with statement closes the file automatically. header.samples supplies the identifiers in header order. The existing validator rejects an empty sample collection. This function does not validate the variant records, genotype quality or genome assembly.

Create tests/test_vcf.py:

"""Tests for reading sample names from VCF headers."""

import pysam
import pytest

from ancestryflow.vcf import read_vcf_samples


@pytest.fixture
def vcf_path(tmp_path):

        "##contig=<ID=1,length=248956422>\n"
        '##FORMAT=<ID=GT,Number=1,Type=String,Description="Genotype">\n'
        "#CHROM\tPOS\tID\tREF\tALT\tQUAL\tFILTER\tINFO\tFORMAT"

        "1\t100\t.\tA\tC\t.\tPASS\t.\tGT\t0/1\t0/0\n",
        encoding="utf-8",
    )
    return path


def test_reads_samples_in_header_order(vcf_path):
    assert read_vcf_samples(vcf_path) == ["donor_02", "donor_01"]


def test_reads_bgzip_compressed_vcf(vcf_path):
    compressed = str(vcf_path) + ".gz"
    pysam.tabix_compress(str(vcf_path), compressed)
    pysam.tabix_index(compressed, preset="vcf")

    assert read_vcf_samples(compressed) == ["donor_02", "donor_01"]


def test_rejects_vcf_without_samples(tmp_path):
    path = tmp_path / "sites_only.vcf"
    path.write_text(
        "##fileformat=VCFv4.2\n"
        "#CHROM\tPOS\tID\tREF\tALT\tQUAL\tFILTER\tINFO\n",
        encoding="utf-8",
    )

    with pytest.raises(ValueError, match="At least one sample ID"):
        read_vcf_samples(path)


def test_reports_missing_vcf(tmp_path):
    with pytest.raises(OSError):
        read_vcf_samples(tmp_path / "missing.vcf")

All inputs are tiny synthetic VCFs. The tests cover header order, a BGZF-compressed and indexed VCF, a sites-only VCF with no samples and a missing file. BGZF is the block-compression format used for indexed VCFs. tabix_compress creates it, and tabix_index writes its index. Reading the header itself does not require indexed regional queries.

"""Utilities for reading variant-file metadata."""
from collections.abc import Iterable
from pathlib import Path

import pysam

from ancestryflow.samples import (
    validate_sample_ids,
    validate_sample_selection,
)


def read_vcf_samples(path: str | Path) -> list[str]:
    """Read and validate sample IDs in VCF header order.

    This checks sample identifiers, not variant records or genotype quality.
    File-opening and parsing errors propagate to the caller.
    """
    with pysam.VariantFile(str(path)) as variant_file:
        return validate_sample_ids(variant_file.header.samples)

def extract_vcf_samples(
    input_path: str | Path,
    output_path: str | Path,
    sample_ids: Iterable[str],
) -> int:
    """Extract sample columns and return the number of variant records written.

    Keeps all variant records and preserves input sample order.
    INFO annotations are copied without recalculation.
    Output must be a new, uncompressed .vcf file.
    """
    input_path = Path(input_path)
    output_path = Path(output_path)

    if output_path.suffix != ".vcf":
        raise ValueError("Output must have a .vcf extension.")

    if output_path.exists():
        raise FileExistsError(f"Output already exists: {output_path}")

    with pysam.VariantFile(str(input_path)) as source:
        requested = validate_sample_selection(
            sample_ids,
            source.header.samples,
        )
        source.subset_samples(requested)

        count = 0
        with pysam.VariantFile(
            str(output_path),
            "w",
            header=source.header,
        ) as destination:
            for record in source:
                destination.write(record)
                count += 1

    return count

subset_samples() selects the genotype columns before iteration begins. The loop processes one record at a time rather than loading the whole VCF into memory. The returned count is the number of variant records written, not the number of samples. Output is currently an uncompressed .vcf; the parent directory must already exist.

INFO annotations are copied without recalculation. An allele frequency stored there may describe the original cohort, so it must not be treated as a frequency calculated from the selected donors. This is sample extraction, not variant filtering or ancestry inference. This initial implementation checks for an existing output before writing, but does not provide atomic publication or cleanup after a mid-stream failure; these remain engineering improvements before production use.

    )

    )

        type=Path,
        required=True,
        help="Sample-list file without a header.",
    )

        "--vcf",

    )

    )
    extract.add_argument(
        "--samples",
        type=Path,
        required=True,

    )

The earlier teaching session used cat > file <<'EOF' to write files. It is only a file-creation convenience: > replaces the file, and the text up to EOF becomes its contents. Using an editor is equally valid and often easier to follow.

pytest>=8,<10 defines an allowed range, not an exact dependency lock. Precise runtime and container pinning belong to later reproducibility checkpoints.

35.10 Common failure

Tests pass, but the count is lower than expected: during the next CLI-integration step, three new test_cli_* functions were accidentally indented inside an existing test. Pytest still reported 28 passing tests, but did not discover the three nested functions. Passing tests alone does not prove that newly added tests ran. Put each standalone test function at the top level, with its def starting at the left margin. Its body remains indented by four spaces.

Use python -m pytest --collect-only -q to list discovered tests without running them, then python -m pytest -q to run them. For that CLI-integration checkpoint, the expected total is 31. The learner corrected the indentation and confirmed all 31 tests passed. The companion example includes that correction.

Editor files appear in git status: an IDE may stage its .idea/ files automatically. Ignore rules do not remove already staged files. Inspect the staging area before the first commit; the Git checkpoint below shows how to remove them from staging while keeping the local files.

35.11 Commit checkpoint

35.11.1 7. Record the first verified version

Run these commands from the ancestryflow project root. First inspect what Git has staged:

git status --short

In the learner’s working copy, the editor had staged .idea/ configuration files. If your status also lists staged .idea/ files, ensure .idea/ appears in .gitignore, then run:

git rm -r --cached .idea

--cached removes the files from Git’s staging area while keeping them on disk. -r includes the directory’s contents. Skip this command if no .idea/ files are staged or tracked. Adding an ignore pattern alone does not unstage files.

Select the five project files and inspect the selection:

git add .gitignore pyproject.toml src/ancestryflow/__init__.py src/ancestryflow/samples.py tests/test_samples.py
git diff --cached --stat

git add stages the named files for the next commit. git diff --cached --stat summarizes that selection. Expect five files, with no environment, genotype data or editor settings.

Create the checkpoint and verify it:

git commit -m "Initialize package with sample validation and tests"
git status --short
git log -1 --oneline

git commit records the staged content locally; -m supplies its description. It does not publish to GitHub. The status command should print nothing, meaning there are no pending changes. git log -1 --oneline shows only the latest commit in compact form.

The learner verified a clean working directory and this commit:

b1b3644 (HEAD -> main) Initialize package with sample validation and tests

Your commit identifier will differ. The pass condition is a clean status and the expected commit message, not a matching identifier. This completes checkpoint 7. See Safe daily Git workflow for more detail about staging and history.

35.13 What to remember

  • Package code is importable independently of the future workflow.
  • Editable installation makes local development convenient.
  • Tests define behavior that future contributors must preserve.
  • Declaring dependency ranges is useful, but it is not full environment locking.
